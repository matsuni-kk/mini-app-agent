# More Criteria（推奨修正）

## 内容チェック（スコアリング）

品質向上のための改善提案。未修正でも合格可能。

| 観点 | 評価基準 | 配点 |
|------|----------|------|
| 差分最小性 | 変更が最小差分で行われている（不要な変更がない） | 30 |
| 整合性 | AGENTS.md/CLAUDE.md/パス辞書との整合が取れている | 25 |
| アセット完備性 | assets/questions/evaluation が揃っている | 20 |
| 追跡可能性 | 変更理由・変更ログが明記されている | 15 |
| 簡潔性 | 説明が簡潔で冗長でない | 10 |

**合計**: 100点

## 推奨項目一覧

### 差分最小性向上
- [ ] 変更箇所が明確に特定されている
- [ ] 変更理由が記載されている
- [ ] 変更前後の差分が明示されている

### 整合性向上
- [ ] AGENTS.mdとの整合確認
- [ ] CLAUDE.mdとの整合確認
- [ ] パス辞書との整合確認
- [ ] 関連Skillとの整合確認

### アセット完備性向上
- [ ] assets/ ディレクトリの整備
- [ ] questions/ ディレクトリの整備
- [ ] evaluation/ ディレクトリの整備
- [ ] SKILL.md の整備

### 追跡可能性向上
- [ ] 変更理由の記載
- [ ] 変更ログ（CHANGELOG）の記載
- [ ] 関連Issue/PRの参照

### 簡潔性向上
- [ ] 説明の簡潔化
- [ ] 重複表現の削除
- [ ] 例示の適切さ

## 許容例外（More対象）

以下は修正推奨だが、未修正でも合格可能。

- 新規作成時は「既存機能維持」チェック対象外
- 外部依存の変更は「外部仕様確認後反映」と記載可
- 軽微な表現の違い（機能に影響なし）

## Good（保持項目）

評価時に特に優れていた点を記録し、次回も維持する。

```markdown
### Goodポイント
- [ ] 変更理由の明確な記載
- [ ] 最小差分での変更
- [ ] 整合性チェックの徹底
```
