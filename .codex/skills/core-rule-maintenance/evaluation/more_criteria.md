# More Criteria（推奨修正）- Core Rule Maintenance

## 内容チェック（スコアリング）

品質向上のための改善提案。未修正でも合格可能。

| 観点 | 評価基準 | 配点 |
|------|----------|------|
| 明確性 | 変更内容が明確で曖昧さがない | 25 |
| トレーサビリティ | 変更理由が記録されている | 25 |
| 一貫性 | 命名規則・表記が統一されている | 20 |
| 保守性 | 将来の変更が容易な構造になっている | 15 |
| ドキュメント | 変更内容が適切に文書化されている | 15 |

**合計**: 100点

## 推奨項目一覧

### 明確性向上
- [ ] 変更の意図が明確に記載されている
- [ ] 新規変数の命名が直感的である
- [ ] 複雑な参照関係にコメントが付いている
- [ ] 破壊的変更の場合、移行手順が記載されている

### トレーサビリティ向上
- [ ] 変更理由（Why）が記録されている
- [ ] 関連Issue/PRへの参照がある
- [ ] 変更履歴に日付と担当者が記載されている
- [ ] 影響範囲の分析結果が残っている

### 一貫性向上
- [ ] 命名規則に従っている（キャメルケース/スネークケース等）
- [ ] 同種の変数で表記揺れがない
- [ ] パスの区切り文字が統一されている
- [ ] 日付フォーマットが統一されている

### 保守性向上
- [ ] 変数の再利用性が高い構造になっている
- [ ] 過度に複雑なネストがない
- [ ] 将来の拡張を見越した設計になっている
- [ ] デバッグが容易な構造になっている

### ドキュメント向上
- [ ] README等の更新が行われている
- [ ] 変更内容がチームに周知されている
- [ ] トラブルシューティングガイドが更新されている
- [ ] 新規ルールの使用例が記載されている

## 許容例外（More対象）

以下は修正推奨だが、未修正でも合格可能。

- 軽微なtypo修正は3環境同期のみで可
- コメント追加のみの変更は影響範囲確認を省略可
- 既存の軽微な表記揺れ（機能に影響しない場合）
- 詳細な変更履歴の未記載（コミットログで代替可）

## Good（保持項目）

評価時に特に優れていた点を記録し、次回も維持する。

```markdown
### Goodポイント
- [ ] 影響範囲の網羅的な分析
- [ ] 明確な変更理由の記録
- [ ] 保守性を考慮した設計
- [ ] チームへの丁寧な周知
```
