# 分岐処理（Branching Logic）仕様書

## 1. 概要

Skill/Subagentにおける条件分岐処理の統一記述ルールを定義する。

**目的**: 
- 分岐条件を検証可能かつ再現可能に記述する
- Skill間の分岐を統一フォーマットで管理する
- 分岐ロジックの可読性・保守性を向上させる

**重要原則**: 
- **分岐判定はSubagentに委譲せず、メインエージェントが直接判定する**
- 分岐先のSkillは**Subagentとして呼び出すのではなく、Skillとして直接実行**する

---

## 2. 分岐処理の種類

### 2.1 事前分岐（Pre-Branching）
- **タイミング**: Skill/Subagent実行**前**に判定
- **用途**: 前提条件チェック、別Skillへの委譲判断
- **記述場所**: `## Instructions` の Step 0 または `## Critical First Step`

### 2.2 事後分岐（Post-Branching）
- **タイミング**: Skill/Subagent実行**後**に判定
- **用途**: 成果物の状態に基づく次Skill選択
- **記述場所**: `triggers/next_action_triggers.md`

---

## 3. 統一記述フォーマット

### 3.1 SKILL.md での分岐記述

```markdown
## Instructions
0. **{分岐名}（分岐判定）**:
   - {Skill名}開始前に、以下の{N}条件をチェックする:
     1. **{条件名1}**: {検証可能な条件記述}
     2. **{条件名2}**: {検証可能な条件記述}
     3. **{条件名3}**: {検証可能な条件記述}
     4. **{条件名4}**: {検証可能な条件記述}
   
   - **判定ロジック**:
     - {ALL/ANY/NONE} 条件を満たす → {アクションA}
     - {ALL/ANY/NONE} 条件を満たさない → `{分岐先skill名}` Skillを直接実行
   
   - **分岐時の引き継ぎ情報**:
     - {引き継ぎ項目1}
     - {引き継ぎ項目2}
     - {引き継ぎ項目3}

1. Preflight:
   ...
```

### 3.2 Subagent での分岐記述

```markdown
## Critical First Step - {分岐名}（Step 0）

**タスク実行前に必ず以下の{N}条件をチェックしてください**:

1. **{条件名1}**: {検証可能な条件記述}
2. **{条件名2}**: {検証可能な条件記述}
3. **{条件名3}**: {検証可能な条件記述}
4. **{条件名4}**: {検証可能な条件記述}

### 判定ロジック
- **{ALL/ANY/NONE}条件を満たす** → {アクションA}
- **{ALL/ANY/NONE}条件を満たさない** → `{分岐先skill名}` Skillを直接実行
  - 分岐時は「{引き継ぎ項目1}」「{引き継ぎ項目2}」「{引き継ぎ項目3}」を引き継ぐ
```

### 3.3 triggers での分岐記述

```markdown
## Step 0 分岐判定（最優先）

### {分岐先Skill名} へ分岐（Skill直接実行）
- 条件: Step 0の{分岐名}で{ALL/ANY/NONE}条件を満たさない場合
- トリガー: 以下のいずれかに該当する場合
  - {条件1の具体的なトリガー}
  - {条件2の具体的なトリガー}
  - {条件3の具体的なトリガー}
  - {条件4の具体的なトリガー}
- アクション: `{分岐先skill名}` Skillを直接実行し、{分岐先での処理内容}
- 引き継ぎ: {引き継ぎ項目リスト}

### {継続先Skill名} へ遷移
- 条件: Step 0の{分岐名}で{ALL/ANY/NONE}条件を満たした場合
- トリガー: {成果物/状態の条件}
- アクション: {継続先}へ遷移し、{継続先での処理内容}
```

---

## 4. 判定ロジックの種類

| ロジック | 意味 | 使用例 |
|---------|------|--------|
| **ALL** | 全条件を満たす | 全ての前提条件が確認できた場合のみ継続 |
| **ANY** | いずれかの条件を満たす | 1つでも問題があれば委譲 |
| **NONE** | どの条件も満たさない | 該当条件がなければスキップ |
| **N of M** | M条件中N個を満たす | 3条件中2条件以上で継続 |

### 4.1 複合ロジックの記述

```markdown
- **判定ロジック**:
  - 条件1-3を**ALL**満たす かつ 条件4-5のいずれかを満たす（**ANY**） → 継続
  - 上記以外 → 委譲
```

## 5. 条件記述のルール

### 5.1 検証可能な条件を書く

| NG例（曖昧） | OK例（検証可能） |
|-------------|-----------------|
| 「ゴールが明確な場合」 | 「Ultimate Goalが1文で説明でき、ステークホルダー間で認識が一致している」 |
| 「情報が足りない場合」 | 「必須フィールドに『未記載』または空欄がある」 |
| 「必要に応じて」 | 「{セクション名}が存在しない、または内容が3行未満」 |
| 「適切なら」 | 「{条件A}かつ{条件B}を満たす」 |

### 5.2 条件のカテゴリ

| カテゴリ | 説明 | 例 |
|---------|------|-----|
| **明確性** | 情報が明確に定義されているか | 「1文で説明できる」「定量化されている」 |
| **合意性** | ステークホルダー間で合意があるか | 「認識が一致している」「承認されている」 |
| **完全性** | 必要な情報が揃っているか | 「必須フィールドが全て埋まっている」 |
| **存在性** | ファイル/セクションが存在するか | 「{ファイル}が存在する」「{セクション}が含まれる」 |

## 6. 引き継ぎ情報の標準項目

分岐時に引き継ぐべき情報の標準セット：

### 6.1 条件ベース分岐の場合
```markdown
- **分岐時の引き継ぎ情報**:
  - 満たさなかった条件とその理由
  - 現時点で判明している情報
  - 参照した資料リスト
  - 制約条件・期限
```

### 6.2 成果物ベース分岐の場合
```markdown
- **分岐時の引き継ぎ情報**:
  - 成果物のパス/内容
  - 成果物のステータス
  - 残課題リスト
  - 次ステップの期待値
```

## 7. subagent_policy への追記ルール

分岐処理を含むSkillでは、`subagent_policy`に分岐ルールを明記する：

```markdown
subagent_policy:
  - **{条件}時の分岐**: Step 0で{条件}を満たさない場合は`{分岐先skill名}` Skillを直接実行する
  - 品質ループ（QC/チェック/フィードバック）は必ずサブエージェントへ委譲する
  - サブエージェントの指摘を反映し、反映結果（修正有無/理由）を成果物に残す
```

**注意**: 分岐先Skillへの移行はSubagentへの委譲ではなく、メインエージェントがSkillを直接実行する。

---

## 8. recommended_subagents への追記ルール

分岐先のSkillおよびQC用Subagentは`recommended_subagents`に登録する：

```markdown
recommended_subagents:
  - qa-skill-qc: 各Skillのevaluation_criteria.mdに基づきQC実施
  - red-team-feedback-loop: 反証/代替案/リスク洗い出し
```

**注意**: 分岐先Skill（例: goal-hypothesis, proposal-hypothesis）はSubagentではなくSkillとして直接実行するため、`recommended_subagents`には登録しない。QC・レビュー用途のSubagentのみ登録する。

## 9. 実装例

### 9.1 goal-discovery の分岐実装

**SKILL.md:**
```markdown
## Instructions
0. **ゴール確定チェック（分岐判定）**:
   - Goal Discovery開始前に、以下の4条件をチェックする:
     1. **Ultimate Goal明確か**: 「何のためのPJか」が1文で説明でき、ステークホルダー間で認識が一致しているか
     2. **ステークホルダー合意あるか**: 主要ステークホルダー（意思決定者・スポンサー）がゴールに合意しているか
     3. **成功定義可能か**: 「何をもって成功とするか」が定量/定性で定義可能か
     4. **顧客課題明確か**: 解決すべき顧客課題が特定されているか
   
   - **判定ロジック**:
     - ALL条件を満たす → 通常のgoal-discoveryを継続（Step 1以降へ）
     - ANY条件を満たさない → `goal-hypothesis` Skillを直接実行
   
   - **分岐時の引き継ぎ情報**:
     - 満たさなかった条件とその理由
     - 現時点で判明している情報（背景、制約、ステークホルダー等）
     - 参照した資料リスト
```

**Subagent:**
```markdown
## Critical First Step - ゴール確定チェック（Step 0）

**タスク実行前に必ず以下の4条件をチェックしてください**:

1. **Ultimate Goal明確か**: 「何のためのPJか」が1文で説明でき、ステークホルダー間で認識が一致しているか
2. **ステークホルダー合意あるか**: 主要ステークホルダー（意思決定者・スポンサー）がゴールに合意しているか
3. **成功定義可能か**: 「何をもって成功とするか」が定量/定性で定義可能か
4. **顧客課題明確か**: 解決すべき顧客課題が特定されているか

### 判定ロジック
- **ALL条件を満たす** → 通常のGoal Discovery継続（下記のワークフロー実行）
- **ANY条件を満たさない** → `goal-hypothesis` Skillを直接実行
  - 分岐時は「満たさなかった条件・理由」「現時点の情報」「参照資料リスト」を引き継ぐ
```

**triggers/next_action_triggers.md:**
```markdown
## Step 0 分岐判定（最優先）

### goal-hypothesis へ分岐（Skill直接実行）
- 条件: Step 0のゴール確定チェックでANY条件を満たさない場合
- トリガー: 以下のいずれかに該当する場合
  - Ultimate Goalが不明確（「何のためのPJか」が1文で説明できない）
  - ステークホルダー間でゴール認識が一致していない
  - 成功の定義が曖昧（定量/定性で定義できない）
  - 解決すべき顧客課題が特定されていない
- アクション: `goal-hypothesis` Skillを直接実行し、3つの並列ゴール仮説を立案する
- 引き継ぎ: 満たさなかった条件・理由、現時点の情報、参照資料リスト

### story-design へ遷移
- 条件: Step 0のゴール確定チェックでALL条件を満たし、Goal Discoveryが完了した場合
- トリガー: ゴール階層（Ultimate → Primary → Sub）が確定し、ストーリー設計が必要な場合
- アクション: `story-design` Skillを実行し、Goal Storyを設計する
```

## 10. チェックリスト

分岐処理を追加する際は以下を確認：

### SKILL.md
- [ ] Step 0 に分岐判定セクションを追加した
- [ ] 条件が全て検証可能（曖昧表現なし）
- [ ] 判定ロジック（ALL/ANY/NONE）を明記した
- [ ] 分岐時の引き継ぎ情報を明記した
- [ ] `subagent_policy` に分岐ルールを追加した（※分岐先はSkill直接実行）

### Subagent
- [ ] `## Critical First Step` に分岐判定を追加した
- [ ] 条件が SKILL.md と一致している
- [ ] 判定ロジックが SKILL.md と一致している
- [ ] `## Next Action Routing` に分岐先を明記した（※Skill直接実行として記述）

### triggers
- [ ] `## Step 0 分岐判定（最優先）` セクションを追加した
- [ ] 分岐先・継続先の両方を記述した
- [ ] トリガー条件が具体的（曖昧表現なし）
- [ ] アクション・引き継ぎ情報を明記した（※「Skill直接実行」と記述）

### CLAUDE.md
- [ ] ワークフロー索引（Section 6）に分岐を反映した
- [ ] パス辞書（Section 7）に必要なパスを追加した
